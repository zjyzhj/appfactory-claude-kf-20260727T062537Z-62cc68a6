# Office Hours · home-view-01（人类阅读，不进 MAP）

## 原始痛点假设
租房/买房者在 1–2 周内实地看 5–15 套房，每套 15–30 分钟。现场信息（采光、噪音、水渍、储物空间、手机信号）靠脑记 + 散落相册，回家后「哪套是哪套」开始糊。决策时刻没有结构：凭印象二选一，或把 40 张无标注照片翻三遍。看房门户（Zillow/Trulia）止步于「约看」，不覆盖「看完之后怎么比」。

## 追问（challenge）
1. **需求真伪**:看房的决策痛苦是「比较」还是「获取房源」？如果用户 80% 的淘汰发生在浏览 listing 阶段（价格/通勤直接 pass)，那现场 scorecard 的使用频次是否低到撑不起一个 App？——回应：scan 显示两个直接 clone(Home Hunter 6754038639、Home viewing 6774289434）均 0 评分，说明形态未被证伪也未被证实；但门户侧「saved homes + notes」的高使用率（Trulia 141 万评分里大量评论围绕 saved/toured homes）佐证记录行为存在，缺的只是决策结构。结论：频次中低（人生事件型），但单次会话价值密度极高（几十万美元/一年租约的决策），按「事件型高价值」而非「日活工具」设计。
2. **最窄楔子**：如果删掉「逐房间 photo-evidence + 权重比较」，只剩通用 checklist，我们是否塌缩成 Checklist – Simple Task Lists(521946672）的换皮？——回应：是。因此 photo-evidence 绑定房间、权重可调、side-by-side 对比表 + verdict 是不可删的最小楔子；checklist 只是输入形态，compare 才是产品。
3. **（必选·narrow wedge 1)Top-N 在哪里仍然辜负用户**:Home Hunter / Home viewing checklist 形态接近但 0 评分、无迭代证据；门户（HotPads/Zumper）的 saved homes 没有逐房间评分与权重；RentCheck(1134017691）面向房东巡检而非租客决策。共同缺口：没有任何一个把「现场证据 → 加权排序 → 一个可分享的结论」串成闭环。
4. **（必选·narrow wedge 2）拿掉楔子是否变 clone**：拿掉 photo-evidence compare 后我们与 0 评分 clone 同形。防线 = 相机/相册证据链 + 权重模型 + verdict 导出，三者写进 non-goals 的「不与 Top-N 竞争面」反面（即必须自营面）。

## 修订后痛点
用户不缺「看房清单」，缺「看房证据的决策化」：每套房的现场观察需要在 10 分钟内落成可横向加权的结构化证据，最终产出一个能说服自己/伴侣/家人的排序结论。

## 目标用户场景
周六下午，Maya 连看 4 套公寓。每套进门打开 App → New Viewing → 按房间走：厨房拍水槽下霉斑、打分、一句备注；卧室量窗朝向打分。走完第 4 套，地铁上打开 Compare：4 套按她的权重（采光 25%、租金 20%、通勤 20%、储物 15%、噪音 10%、其他 10%）排出 #1，并把带照片的对比结论发给男友。

## 现状与代价
现状：相册 200 张混拍 + 备忘录碎句 + 门户 saved list。代价：决策周延长、复看约不到、选错房（一年租约损失数千美元/搬家成本），或决策被最近看的一套「近因偏差」绑架。

## 最痛时刻 / 最窄楔子
最痛时刻 = 看完第 3 套后「第 1 套厨房什么样来着？」——证据回溯失败。最窄楔子 = 逐房间 photo-evidence scorecard → 权重可调 → side-by-side compare → verdict。

## 参考 app 为何不够
- Home Hunter - Smart Checklist（6754038639,0 评分）：形态最接近但无权重比较与证据导出的市场证据，0 评分 = 未验证。
- HotPads(345957475)/Zumper(678683201)：止步于找房与约看，saved homes 无逐房间评分。
- RentCheck(1134017691)：房东/物业巡检视角，非租客决策比较。
- Checklist – Simple Task Lists(521946672)：通用清单，无房间/权重/证据对象。

## 痛点 → 最小功能桥
证据回溯失败 → 房间×指标 scorecard + 现场拍照绑定房间；比较失焦 → 权重模型 + 自动排序 compare 表；结论难分享 → verdict 卡（图）导出到相册。

## v0 价值判断
删掉 compare/权重，产品死；删掉导出，决策闭环破一半（可与伴侣共决策是核心场景）;v0 无账号、全离线即可交付完整价值——AI 非必要（relay key 当前不可用，产品本身也不需要）。v0 成立。
